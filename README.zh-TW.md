# cfuel

> English: [README.md](README.md)

<img src="art/beep.gif" width="240" align="right" alt="Beep 在挖礦">

**Claude Code 帳號的油表。**

手上有多個 Claude 帳號時,兩件事會自己發生:買來的額度沒用到就過期,因為它躺在你沒
在用的那個帳號上;還有長時間的工作跑到一半斷掉,因為你正在用的帳號在兩次檢查之間撞
到上限。

`cfuel` 用一個畫面回答這兩件事,而且——如果你允許——在任何一件發生前就把你換走。

<br clear="right">

---

## 安裝

需要 **Python ≥ 3.12**。`uv` 會自己抓一個合適的版本,不用動你系統的 Python。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh          # 還沒裝 uv 的話
uv tool install "git+ssh://git@github.com/kuohsuanlo/claude-fuel.git"
```

只裝一個指令:**`cfuel`**。直接打開畫面,後面接參數就是帳號 CLI(`cfuel add`、
`cfuel list`……)。

它不佔用上游 claude-swap 的任何指令名,所以兩者可以並存、共用同一份帳號。要更新就
用 `--force --reinstall` 重跑安裝——`uv tool upgrade` 不會重抓 git 來源。

## 讀懂這個畫面

![cfuel 標註圖](art/screenshot-annotated.png)

### ① 標題列 — 什麼快要沒了

顯示 `nothing expiring within 24h`,或是那筆快到期的額度:`dev5 7d 28% expiring
within 24h`。

有多筆同時到期時,它**計數**其餘的(`+1 more`)而不是加總。百分比是「某個方案的某
個視窗」的比例,而池子大小各不相同,所以一個方案的 28% 加另一個的 10% 根本不是數
字。點名一筆、其餘計數,是誠實能講到的極限。

`AUTO` 代表引擎已武裝。`switch at 97%` 是目前生效的門檻。

### ② 油箱剩多少、還能撐多久

`430% ≈6h` — 全隊在該視窗的剩餘額度,以及照目前速度還能撐多久。

**超過 100% 是常態。** 單位是「一個帳號的該視窗」,所以三台沒動過就是 300%。正規化
成全隊比例的話,一台的隊伍和六台的隊伍會印出同樣的「45%」。

續航用**時間**表示,因為時間是唯一不需要換算的單位。百分比是不同池子的比例;token
又沒人拿來預算。「我還能繼續工作多久」才是實際在問的問題。

算法是「輪流燒過每個帳號、各用自己的速率」所需的時間總和——成立的理由是**工作屬於
機器,不屬於帳號**:換帳號不會改變正在跑的東西。

### ③ 進度條與兩個標記

彩色段是還剩的,虛線軌道是已用的。每個帳號的份額往左靠齊,所以**彩色段的長度就是全
隊剩餘的燃料**,裡面的端點是帳號之間的邊界。

**顏色是帳號的身分** — 依「距離該帳號的週重置還有多遠」排一次,最遠的綠、最近的紅,
三條共用同一套。三條的排序也用同一個排名,所以光譜永遠是左綠右紅,而同一個顏色在每
一列意思相同。

顏色**刻意不跟隨**策略用的浪費風險。風險是「餘裕**除以**距離」,所以一個只剩 8 點的
帳號反而算出全場最平靜——因為它沒東西可失去。「快用完」和「還很久」會塗成同一種綠。

- **上方 `▼`** — 在**那個視窗**裡最早到期的帳號。沒東西可失去時隱藏。
- **下方 `▲`** — 現在正在被消耗的帳號。

**這兩個標記之間的落差就是這個畫面存在的理由。** 它們回答不同問題——什麼先死、我在
燒什麼——落差大就代表有東西正在被浪費。

每個絕對時間都帶星期(`8/25 Tue 07:00`)。只有日期的話還要查一次:那是明天?週末?
下週?而那個判斷正是這個數字存在的目的。

### ④ 各帳號數字

`5 59% 54m` — 帳號編號、該視窗已用多少、何時重置。順序與顏色和進度條一致。

### ⑤ per-model 限制有沒有生效

`running · sandbox`,或 `not running`。

帳號除了 5h 和 7d 之外,每個模型還有各自的週視窗(例如 Fable)。那個視窗只在你真的
在用該模型時才有意義——但判定涵蓋**整台機器**,所以另一個不相干的 session 在跑 Fable
就會把它釘住,於是每個 Fable 用光的帳號都會被讀成「不能用」。

這一行點名是誰造成的。沒有它,你看得到「有個限制生效中」,卻永遠看不到是誰。

沒生效的視窗**保留它的進度條**而不是消失:那筆額度是真的、也照樣會過期,只是此刻不
構成限制。

### ⑥ 燃燒速率,以及它推得的門檻

`0.017%/s · 1% every 58s · suggested 99%`

速率是本地量的,來自 Claude Code 自己的 transcript——每筆請求都記了 token 數,讀它
不花任何成本。機器上**所有** session 都會被看到,不只你開 `cfuel` 的那個。

兩種形式都顯示,是因為門檻本質上是「你要留多少預警時間」的決定,而「幾秒一個百分點」
直接回答了它。

`suggested` 是目前速率撐得住的最高門檻。按 `r` 採用它——但**只會往嚴格的方向**:機
器閒下來時建議值是 99,採用它等於把一個刻意設成 94 的人的保護額度交還回去。

### ⑦ 帳號清單

每個帳號的每個視窗、重置時刻與倒數。`(!)` 標記已達上限;`(ahead of pace)` 標記消耗
速度超過該視窗補充的速度。

### ⑧ Beep 與天空

Beep 是儀表,不是裝飾。**有 token 在燒時他就挖礦**,揮動速度跟著燃燒速率。**九十秒
沒有任何消耗他就睡著**——這件事任何數字都講不出來:燃燒速率是 0,到底是閒著還是壞了。

他上方是真實的天空:太陽或月亮依你的本地時鐘定位,配上你所在地的真實天氣。它**不花
任何 token**——太陽是時鐘的算術,天氣是背景執行緒上一次很小的免金鑰請求,每小時幾
次,而且會存到磁碟。沒有網路時它畫晴天,而不是把預設值當成量測結果呈現。

### ⑨ Session

機器上每一個 session,用你替它取的名字,配上 Claude Code 自己回報的狀態,以及**它
正在跑的模型**。

它們全都在消耗同一個使用中的帳號,所以武裝引擎會一次移動全部。模型那一欄正是 ⑤ 的
解答:一個 session 在跑 Fable 就足以把那個視窗釘住。

數量旁邊是這台機器有史以來的總量,每一列也標出該專案的份額。`m` 可以隱藏這些數字。

### ⑩ API pricing

同一筆消耗依模型拆開。

**token 是量出來的,金額是用一份標了日期的價目表換算的** — 日期印在畫面上,因為價
格會變,而來自過期表的數字**只有在它說出用了哪張表時才誠實**。

**金額由快取讀取決定。** 這台機器 66B token 裡有 63B 是快取讀取,而它的價格是輸入價
的十分之一(寫入則是 1.25 倍)。檯面上的每模型單價幾乎解釋不了這個數字——所以快取
那一欄就放在金額旁邊。

**這不是帳單。** 訂閱制的帳單是固定的。這是「同樣的工作走 API 計價會花多少」。

### ⑪ 快捷鍵

| 按鍵 | 作用 |
| --- | --- |
| `a` | 自動切換 開/關(啟動時為**開**) |
| `↑` `↓` | 選擇帳號 — 只在自動**關閉**時可用 |
| `enter` | 切換到選中的帳號 |
| `t` 之後 `←` `→` | 調整門檻 — **會寫進 settings.json** |
| `r` | 採用建議門檻(只會調緊) |
| `h` | 隱藏引擎的 log 行 |
| `m` | 隱藏 token 與金額 |
| `q` | 離開 |

武裝與解除**不會干擾顯示**:兩種狀態下數值照樣持續更新。因為你是**看完畫面之後**才
決定要不要武裝,一個會重置你正在看的東西的開關會讓這件事做不到。

## 它怎麼決定

### 先燒快過期的

預設策略 `waste-first` 依「**週餘裕 ÷ 距離該視窗重置的小時數**」排序——也就是額度正
以多快的速度走向浪費。

上游的預設是依「還剩多少」排序,結果穩定地停在「期限最長」的那個帳號上,也就是最沒
有浪費危險的額度。在真實艦隊上量到:49 點在 20 小時內到期,是 2.4 %/h,而使用中的帳
號是 0.46 %/h——工具一直待在使用中的帳號,直到那 49 點過期。

只看期限排序則有相反的毛病:它會為了一個「重置比較早、但只剩 2 點可救」的帳號搬家。

```bash
cfuel config set autoswitch.strategy waste-first    # 預設
cfuel config set autoswitch.strategy consume-first  # 只看最早重置,不管剩多少
cfuel config set autoswitch.strategy best           # 上游:剩最多
```

### 先燒已經失去某個模型的帳號

Fable 視窗已經用光的帳號,只能再吸收非 Fable 的工作;Fable 完好的帳號兩種都能吸收。
所以拿一個 Opus 的回合去燒第二種,**摧毀了只有它能提供的額度**;燒第一種則摧毀零。

引擎因此優先榨乾能力較差的帳號,而且**嚴格更沒彈性的候選人會直接跳過風險門檻**——否
則這條規則永遠不會觸發,因為「只剩無模型額度」的帳號按定義就是全場最平靜的那個,從
來不會成為目標。

這是支配關係,不是調出來的偏好:先榨乾它永遠不會更差,而且只要哪天有任務需要你留下
的那個模型就更好。兩個例外:該模型真的在跑時解除,以及候選人的額度 24 小時內就要到
期時解除——用掉它,勝過為一個可能不會來的任務留著視窗。

### 在撞牆之前換,不是撞到才換

用量端點大約允許**每小時 28–30 次請求**,所以你的使用率最快也只能三分鐘取樣一次。一
個吃重的平行回合在那段時間裡會跨過十個百分點。

門檻是一個**位置**,而「照平均值看起來安全」的位置,會在下一次取樣落地之前就被跨過。
所以燃燒速率改從 transcript 量,實際觸發值取「你的門檻」與「目前速率撐得住的值」兩者
較低的那個。

**保留量是一整個引擎 tick,外加一個下限。** 每次 tick 都可能要抓用量,而那個預算正是
迴圈不能每秒跑的原因——所以 tick 間隔**就是**暴露時間。只保留 10 秒卻每 60 秒 tick 一
次,等於六分之五的缺口沒防到;而一個真實的 agent 就是從那裡被切斷的:0.062 %/s 等於
每分鐘 3.7 點,對上 0.6 點的保留量。

下限對「量到 0」同樣適用。量到零是關於上一分鐘的陳述,不是對下一分鐘的承諾,而重回合
開始的前一刻正是保留量最重要的時候。

```bash
cfuel config set autoswitch.burstGuard false     # 關掉
cfuel config set autoswitch.burstFloorPct 2      # 保留比預設 1 更多
```

**同一份保留量也把關目的地。** 對「要搬過去的帳號」只要求 `餘裕 > 0`,是同一個錯誤晚
一步發生:引擎曾在燃燒 0.75 %/s 時落在一個 5 小時視窗只剩 3% 的帳號上——那是四秒——任
務一落地就死,而更寬裕的帳號被跳過,因為排序鍵完全沒有提到短視窗。

### 只計算你真的在用的模型限制

`autoswitch.model` 預設 **`all`**:API 只會替「帳號真的有的限制」回報 per-model 視窗,
而存在的限制填滿時一定會擋住工作。忽略它不是外觀問題——一個顯示 `Fable 100%` 和
`7d 95%` 的帳號曾被排成**最該繼續燒的帳號**,因為引擎讀的是那個模型已經沒有的 7d 餘裕。

但**哪些視窗當閘是量出來的,不是宣告的**。一個模型在「近五分鐘有流量」或「它是你選定
的模型」時當閘——Claude Code 會把選擇存起來,所以用 `/model` 切換在你花掉任何東西之前
就算數,這是單靠觀測永遠做不到的。

機器閒置時不放寬任何東西:「在跑 Opus 不是 Fable」和「什麼都沒跑」在 token 流裡長得一
模一樣,意思卻相反。

```bash
cfuel config set autoswitch.model none        # 不理會 per-model 限制
cfuel config set autoswitch.model Fable,Opus  # 只看這些
cfuel config set autoswitch.measuredModelMix false   # 一律照清單當閘
```

### 拿同樣的東西相比

用量 API 只回報使用率,所以 20× 方案的 40% 和 5× 方案的 40% 對它來說一模一樣,實際工
作量卻差四倍。進度條寬度依方案大小加權——設定的、量出來的,或兩者都還不知道時等權。

同一課也適用於燃燒尺度:token 是成本形狀的代理量,不是供應商的帳,所以「token 換百分
比」的常數是拿實際到達的取樣去校正的——**逐帳號、逐視窗**。兩半都是量出來才發現的
bug:把 token 配到 **binding** 視窗,會在同一個帳號的連續三筆取樣量到 411k、2,148k、
348k tokens/%,因為 binding 視窗會隨短視窗重置在 5h 和 7d 之間跳——兩把尺平均在一起,
把速率低估了三倍。

```bash
cfuel config set autoswitch.accountWeights "1=20,2=5,3=5"
```

## 指令

上游能做的事全部收在同一個名字底下。`cfuel help` 印出完整清單。

| 指令 | 作用 |
| --- | --- |
| `cfuel` | 開啟畫面 |
| `cfuel add` | 加入目前登入的帳號 |
| `cfuel list` / `ls` | 列出帳號與用量 |
| `cfuel status` | 顯示目前帳號 |
| `cfuel switch [num\|email]` | 輪替,或跳到指定帳號 |
| `cfuel remove` / `disable` / `enable` | 管理輪替名單 |
| `cfuel run <num\|email> [-- ...]` | 以某帳號執行,只影響這個終端機 |
| `cfuel map` / `alias` / `swap` / `move` | 目錄對應、別名、槽位順序 |
| `cfuel auto` | 無介面的自動切換迴圈 |
| `cfuel config [set KEY VALUE]` | 顯示或修改 settings.json |
| `cfuel export` / `import <path>` | 在機器之間搬帳號 |
| `cfuel upgrade` | 自我更新 |

## 設定

`settings.json` 和你的帳號放在一起(Linux 上是 `~/.local/share/claude-swap/`)。
`cfuel config` 會列出全部;這個 fork 新增的鍵:

| 鍵 | 預設 | 意義 |
| --- | --- | --- |
| `autoswitch.strategy` | `waste-first` | `waste-first`、`consume-first`、`best` |
| `autoswitch.burstGuard` | `true` | 讓量到的速率提早觸發 |
| `autoswitch.burstFloorPct` | `1` | 一定保留的百分點,疊加在速率之上 |
| `autoswitch.model` | `all` | 會當閘的 per-model 限制;`none` 為忽略 |
| `autoswitch.measuredModelMix` | `true` | 只在模型真的在跑時才當閘 |
| `autoswitch.accountWeights` | — | 方案相對大小,`1=20,2=5` |

**只有和預設不同的值會被寫入。** 把每個欄位都寫出去,會在你第一次微調任何一個設定時
就把整段凍住,之後任何預設值的改進都到不了已經在跑的機器。

**切換會移動機器上的每一個 session。** 它們共用同一份登入。

## 開發

```bash
git clone git@github.com:kuohsuanlo/claude-fuel.git
cd claude-fuel
uv sync
uv run pytest -q                       # 2356 條測試
uv tool install --force --reinstall .  # 安裝你的工作目錄版本
```

`art/beep/` 保留了 sprite 的摳圖過程:`PIXELS.txt` 是 Beep 逐像素的傾印,含調色盤與每
個部位的標記;`inspect.png` 是同一份放大並標上座標。

## 上游與致謝

**cfuel 是 [realiti4/claude-swap](https://github.com/realiti4/claude-swap)(`cswap`
指令)的 fork。** 帳號管理——新增、憑證保存、輪替、session 與選單列模式、儀表板——都
是上游的成果,而且和那邊的文件所述一樣運作。這個 fork 加的是回答**何時**與**為什麼**
的部分。

磁碟上的格式沒有改變,所以可以直接裝在既有的 claude-swap 之上而不動到你的帳號,也可
以退回去。上游以 `upstream` remote 追蹤:

```bash
git fetch upstream && git merge upstream/main
```
